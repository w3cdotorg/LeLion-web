# Phase 0 : dépôt et CI Web seule

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mettre LeLion-web en ligne sur GitHub, débarrassé de ce qui ne sert plus dès aujourd'hui
(exports desktop, Releases), avec une CI verte qui publie l'export Web en artefact.

**Architecture:** Aucune ligne de jeu ne change. On crée le dépôt `w3cdotorg/LeLion-web` depuis le
clone local `~/Sites/LeLion-web` (historique de LeLion-multi compris, remote `multi`), on pousse
`main` tel quel (spec et plans), puis une branche `phase-00-web-seul` retire les exports desktop, le
job Release et la doc du LAN, par une PR.

**Tech Stack:** GitHub (`gh`), GitHub Actions, Godot 4.7.2 (export Web).

**Spec:** `docs/superpowers/specs/2026-10-01-multijoueur-en-ligne-design.md` (§3.2, §11) et la
feuille de route `docs/superpowers/plans/2026-10-01-en-ligne-feuille-de-route.md` (ligne 0).

## Global Constraints

- Dépôt **public**, nommé `w3cdotorg/LeLion-web`, **sans lien de fork** (pas `gh repo fork`).
- Chaque commande `gh` porte `--repo w3cdotorg/LeLion-web`.
- La découverte LAN, l'écran Réseau et le transport ENet **restent** (retirés en phases 1 à 3 bis).
- `config/version` reste `0.19` (elle monte en phase 1, avec le protocole).
- Aucun secret dans le dépôt.
- Messages de commit en français, avec les lignes d'attribution de la session.

## Review Focus

1. Un push sur `main` ou une PR doit encore exporter le Web et échouer si `index.html` manque
   (étape « Exporter en Web » gardée, artefact `LeLion-web` en `if-no-files-found: error`).
2. Aucune trace des exports retirés : ni `Windows Desktop`, `Linux`, `macOS`, `wrestool`, `release`
   dans `ci.yml` et `export_presets.cfg`, ni lien vers les Releases de LeLion-multi dans le README
   (Task 2, étape 5 et Task 3, étape 3 : `grep` qui doit être vide).
3. `export_presets.cfg` tronqué mais encore lisible par Godot : seul `[preset.0]` et
   `[preset.0.options]` restent, et l'export Web de la CI le prouve (Task 4, étape 2).
4. Pousser un tag ne doit plus rien déclencher qui réclame des artefacts disparus (déclencheur
   `tags` et job `release` retirés ensemble : Task 2, étape 5).
5. `gh` ne vise pas le mauvais dépôt : `gh repo set-default` fait, et vérifié (Task 1, étape 4).
